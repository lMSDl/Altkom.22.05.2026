# Test Failures due possible code bugs

## Hangman.UnitTests.csproj - RenderGame_CallsLocalizationForWord
- **Confidence**: High
- **Test File**: Hangman.UnitTests\Presentation\ConsoleRendererTests.cs
- **Bug Location**: Hangman\Presentation\ConsoleRenderer.cs@98

### Analysis
The RenderGame method calls Console.Clear() as its first statement (line 98). In non-console test environments, Console.Clear() throws an IOException, which prevents execution from reaching the loc.Get() calls that the test is verifying. The test was correctly skipped because of this production code issue. The fix belongs in the production code — Console.Clear() should be guarded against IOException.

### Suggested Fix
In `ConsoleRenderer.cs`, wrap the `Console.Clear()` call in a try/catch to handle the `IOException` thrown in non-console environments:

```csharp
public void RenderGame(GameState game, GameLanguage language)
{
    try { Console.Clear(); } catch (IOException) { /* non-console environment */ }
    Console.WriteLine(HangmanStates[Math.Clamp(game.WrongAttempts, 0, game.MaxAttempts)]);
    Console.WriteLine($"{loc.Get(MessageKeys.Word, language)}: {game.MaskedWord}");
    Console.WriteLine($"{loc.Get(MessageKeys.WrongAttempts, language)}: {game.WrongAttempts}/{game.MaxAttempts}");
    Console.WriteLine($"{loc.Get(MessageKeys.UsedLetters, language)}: {string.Join(", ", game.GuessedLetters.OrderBy(c => c))}");
}
```

After this change, the test can be un-skipped by removing the `Skip` parameter from the `[Fact]` attribute.
